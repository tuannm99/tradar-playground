# Glossary

Short definitions with a pointer to the chapter that explains each in depth.

- **ACID** — atomicity, consistency, isolation, durability. [1.4](../01-fundamentals/04-transactions.md#1-acid-precisely)
- **Anomaly** — an observable result of insufficient isolation (dirty read, lost update, write skew…). [1.4](../01-fundamentals/04-transactions.md#2-anomalies)
- **Autovacuum** — PostgreSQL's background cleanup and statistics process. [2.1](../02-postgres/01-storage-and-mvcc.md#4-vacuum)
- **Bitmap scan** — PostgreSQL plan collecting matching row addresses, then reading heap pages in order. [2.3](../02-postgres/03-planner-and-explain.md#5-node-reference)
- **Bloat** — dead or unused space in tables/indexes. [2.1](../02-postgres/01-storage-and-mvcc.md)
- **BRIN** — block range index; tiny min/max summaries. [2.2](../02-postgres/02-indexes.md#6-brin-tiny-indexes-for-huge-ordered-tables)
- **Buffer cache / pool** — in-memory page cache of the database. [1.1](../01-fundamentals/01-storage.md#3-the-buffer-cache)
- **B-tree / B+tree** — sorted, balanced tree used for most indexes. [1.1](../01-fundamentals/01-storage.md#6-tree-structures-and-the-write-path)
- **Cardinality (estimate)** — number of rows an operator produces; also "distinct values". [1.3](../01-fundamentals/03-query-execution.md#2-declarative-queries-cost-based-choice)
- **CDC** — change data capture; streaming row changes from the log. [5.1](../05-architecture/01-oltp-vs-olap.md)
- **Checkpoint** — a point where dirty pages are flushed so recovery can start there. [1.1](../01-fundamentals/01-storage.md#7-durability-the-write-ahead-log)
- **Clustered index** — table stored in primary-key order. [1.1](../01-fundamentals/01-storage.md#5-how-rows-are-organised)
- **Column store** — values stored per column. [1.1](../01-fundamentals/01-storage.md#4-row-store-vs-column-store)
- **Compaction** — merging immutable files/parts in the background (LSM, MergeTree). [1.1](../01-fundamentals/01-storage.md#6-tree-structures-and-the-write-path)
- **Covering index** — index containing all columns a query needs. [1.2](../01-fundamentals/02-indexing.md#4-covering-index-only-access)
- **Deadlock** — circular lock wait; the engine aborts one participant. [1.4](../01-fundamentals/04-transactions.md#5-locks-and-deadlocks)
- **Dirty page** — modified in memory, not yet written to the data file.
- **ESR** — Equality, Sort, Range index field ordering guideline. [4.2](../04-mongodb/02-indexes.md#4-compound-indexes-and-esr)
- **Extended statistics** — multi-column statistics (PostgreSQL). [2.3](../02-postgres/03-planner-and-explain.md#multi-column-predicates-and-extended-statistics)
- **fsync** — OS call forcing data to durable storage; the cost of commit. [1.1](../01-fundamentals/01-storage.md#7-durability-the-write-ahead-log)
- **Granule** — ClickHouse's 8 192-row unit of reading. [3.1](../03-clickhouse/01-storage-mergetree.md#1-anatomy-of-a-mergetree-table)
- **Group commit** — several commits sharing one fsync.
- **HOT update** — PostgreSQL heap-only tuple update that avoids index changes. [2.1](../02-postgres/01-storage-and-mvcc.md#3-hot-updates)
- **Isolation level** — how much concurrent transactions are shielded from each other. [1.4](../01-fundamentals/04-transactions.md#3-isolation-levels)
- **Keyset pagination** — paging by "after this key" rather than offset. [1.3](../01-fundamentals/03-query-execution.md#5-sort-aggregate-limit)
- **Keeper** — ClickHouse's Raft-based coordination service. [3.5](../03-clickhouse/05-architecture.md#2-replication-replicatedmergetree-and-keeper)
- **Lightweight delete** — ClickHouse `DELETE FROM` that masks rows. [3.4](../03-clickhouse/04-consistency-and-mutations.md#lightweight-delete)
- **LSM tree** — log-structured merge tree. [1.1](../01-fundamentals/01-storage.md#6-tree-structures-and-the-write-path)
- **Materialized view** — stored query result; in ClickHouse an insert trigger. [3.4](../03-clickhouse/04-consistency-and-mutations.md#4-incremental-aggregation-with-materialized-views)
- **MergeTree** — ClickHouse's core table engine family. [3.1](../03-clickhouse/01-storage-mergetree.md)
- **MVCC** — multi-version concurrency control. [1.4](../01-fundamentals/04-transactions.md#4-how-engines-implement-isolation)
- **Mutation** — ClickHouse's asynchronous `ALTER ... UPDATE/DELETE`. [3.4](../03-clickhouse/04-consistency-and-mutations.md#2-mutations-alter-update-and-delete)
- **N+1** — one query per item instead of one batch. [1.1](../01-fundamentals/01-storage.md#1-the-cost-hierarchy)
- **OCC** — optimistic concurrency control. [1.4](../01-fundamentals/04-transactions.md#4-how-engines-implement-isolation)
- **Oplog** — MongoDB's replication log (capped collection). [4.1](../04-mongodb/01-storage-wiredtiger.md#replication-log-the-oplog)
- **Page / block** — fixed-size unit of storage I/O. [1.1](../01-fundamentals/01-storage.md#2-pages-the-unit-of-io)
- **Part** — an immutable directory of sorted column files in MergeTree. [3.1](../03-clickhouse/01-storage-mergetree.md)
- **Partition pruning** — skipping partitions that cannot match. [5.3](../05-architecture/03-partitioning-and-sharding.md)
- **Planner / optimizer** — chooses the execution plan. [1.3](../01-fundamentals/03-query-execution.md)
- **Projection** — ClickHouse hidden alternate sort/aggregation inside parts. [3.2](../03-clickhouse/02-indexes-and-pruning.md#5-projections-and-materialized-views)
- **Quorum** — majority of replicas required for an operation. [5.2](../05-architecture/02-replication-and-consistency.md)
- **RPO / RTO** — recovery point/time objective. [5.2](../05-architecture/02-replication-and-consistency.md#7-practical-decisions)
- **Read concern / write concern** — MongoDB's freshness/durability knobs. [4.4](../04-mongodb/04-transactions-and-concerns.md)
- **Replication lag** — how far a follower is behind. [5.2](../05-architecture/02-replication-and-consistency.md)
- **Selectivity** — fraction of rows matching a predicate. [1.2](../01-fundamentals/02-indexing.md#1-what-an-index-buys)
- **Serializable** — outcome equals some serial order. [1.4](../01-fundamentals/04-transactions.md#3-isolation-levels)
- **Shard key** — field(s) deciding data placement across shards. [4.5](../04-mongodb/05-architecture.md#choosing-a-shard-key)
- **Skip index** — ClickHouse block-level summary index. [3.2](../03-clickhouse/02-indexes-and-pruning.md#4-data-skipping-indexes)
- **Snapshot isolation** — each transaction reads a consistent snapshot. [1.4](../01-fundamentals/04-transactions.md#3-isolation-levels)
- **Sparse index** — one entry per block of rows. [3.2](../03-clickhouse/02-indexes-and-pruning.md#1-the-sparse-primary-index)
- **Split brain** — two leaders at once. [5.2](../05-architecture/02-replication-and-consistency.md#5-failure-failover-and-split-brain)
- **SSI** — serializable snapshot isolation. [1.4](../01-fundamentals/04-transactions.md#4-how-engines-implement-isolation)
- **TOAST** — PostgreSQL out-of-line storage of large values. [2.1](../02-postgres/01-storage-and-mvcc.md#1-where-rows-live)
- **TTL** — automatic expiry of data. [3.1](../03-clickhouse/01-storage-mergetree.md#7-ttl-data-lifecycle)
- **Vacuum** — reclaiming dead tuples; freezing xids. [2.1](../02-postgres/01-storage-and-mvcc.md#4-vacuum)
- **Visibility map** — per-page "all visible" bits. [2.2](../02-postgres/02-indexes.md#index-only-scans-need-the-visibility-map)
- **WAL** — write-ahead log. [1.1](../01-fundamentals/01-storage.md#7-durability-the-write-ahead-log)
- **Working set** — pages the workload touches regularly. [1.1](../01-fundamentals/01-storage.md#3-the-buffer-cache)
- **Write skew** — anomaly where disjoint writes jointly break an invariant. [1.4](../01-fundamentals/04-transactions.md#2-anomalies)
